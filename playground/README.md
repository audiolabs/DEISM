It requires a separate license from Fraunhofer beyond internal, non-commercial use for evaluation, testing, and academic research.

Install DEISM and run `deism-playground` from any directory. The command serves
this UI on `127.0.0.1`, starts one persistent Python simulation process, and opens
your browser. Ctrl+C shuts down both. `--no-browser` and `--port 8765` are optional.
Normal wheels and editable installs include the built UI and original example
MAT datasets; users need no Node.js or manual build.

**Run Python DEISM** executes the public `DEISM` workflow. Imports and Numba
initialization are reused between runs; one simulation is active at a time.
Cancel terminates that process, and the next run starts a fresh one. The Run
button shows the folder where completed runs are archived. Run details
show package/native paths, version, thread count, per-stage computation times,
startup and browser latency. The adapter rejects missing accelerated capabilities
instead of falling back. It retains the installed defaults for Numba shoebox
images, parallel Numba solving, compact C++ convex images, and fast ARG refitting.

`demo.html` is a browser-only JavaScript demo served locally over HTTP alongside its `data/` folder. It has no
native performance guarantee or validated high-order numerical parity. In that
mode the full run is labeled **Run offline JavaScript**. Preview always uses
JavaScript with reduced settings.

## Modes and workflow

The selector before **01 · Room** controls both custom settings and presets:

- **RTF:** frequency start/end/step inputs and the RTF plot.
- **RIR:** sampling rate and output length inputs, with both RTF and RIR plots.
  The solver derives its frequency spacing from T60; output length controls
  padding/truncation after the inverse FFT, not frequency resolution.

Accurate runs always execute the full workflow. Shoebox directivities precede
image generation; convex image paths precede the source-directivity refit.
Optional path fluctuations follow image generation. RIR synthesis uses the
Python solver's zero-DC convention and bandpass window. The displayed RTF is
retained before that window is applied.

Every run captures its parameters and preset identity before loading data.
Editing during a run leaves the completed result stale. Invalid inputs,
coincident source/receiver positions, missing required material assignments,
and non-finite output produce errors rather than successful curves.

## Materials and geometry

Both room types provide one row per wall. Absorption has one numeric input;
normalised complex impedance has independent real and imaginary inputs.
Focus, hover, or click a wall row to highlight the corresponding face. Use
**Apply selected wall to all** for uniform materials. T60 input is shoebox-only.

Convex geometry is the hull of its vertices. Surviving faces retain their
materials by stable vertex membership, independent of hull ordering. New,
split, or merged faces are marked for review; confirm their material rows
before running. A geometry edit refreshes both the wall table and position
bounds. Room presets also retain the room rotation for source and receiver
orientation frames, matching Python's ARG workflow.

## Directivity data

The dataset catalog is generated by scanning every `.mat` file in
`examples/data/sampled_directivity/source` and `receiver`. The selector offers
every sampled-sphere dataset for the role currently shown (currently seven
source and seven receiver datasets) under a readable label derived from the
filename tokens plus the sphere radius, e.g. `Speaker_small_sph_cyldriver_source.mat`
becomes "Small spherical speaker, cylindrical driver · r 0.2 m"; the filename
stays in the option tooltip and in the run provenance. The six single-point
`*_directpath.mat` responses are excluded from the selector because they lack
sphere directions and radius. Only applicable sampled datasets are offered.

The shared filename `speaker_cuboid_cyldriver_1.mat` has distinct source and
receiver data/radii. The receiver copy uses a separate internal ID; both appear
as "variant 1" in their respective role lists. Re-run the converter and builder
after adding local files to refresh the catalog and separate JSON datasets
(`tools/playground_directivity.py --catalog-only` rewrites only the catalog).

Python loads the original MAT pressure, directions, radii, and complete frequency grids.
Preview JSON files retain original frequencies and directions, with float32 pressure.
Both built HTML pages are approximately 0.32 MB and contain no pressure datasets.
Only selected datasets are fetched from `data/` and cached in the page session.
The native launcher regenerates these ignored JSON files from the original MAT data before serving the page. JSON datasets are neither tracked in Git nor included in the Python package. Python simulations use the original MAT files.

Original MAT datasets use Git LFS. Run `git lfs install` and `git lfs pull` after cloning. Browser-only use through a local HTTP server requires running `python tools/playground_directivity.py` first; a static HTML page cannot itself convert MAT files.

Sampled directivities follow the Python class when the simulation grid differs
from the dataset grid (`init_source_directivities` / `interpolate_functions`):
the sampled pressure is interpolated per direction with shape-preserving PCHIP
on the real and imaginary parts, and bins below the first or above the last
dataset frequency hold the edge value instead of extrapolating. The engine
(`engine/directivity.js`, `interpolateDataset`) does the same, so RIR grids and
arbitrary RTF bands run in both tiers; a warning states how many bins were
interpolated and how many hold the edge value, and the Directivity card flags a
requested band that extends beyond the dataset. Bins that coincide with dataset
bins reproduce the samples exactly, so the JASA and IWAENC presets on the full
example grid are unchanged. The request field `directivityFreqPolicy` accepts
`"interpolate"` (default) or `"exact"`, which refuses any grid other than the
dataset's own. Monopoles need no dataset.

## Preview and plots

Preview uses LC, reflection order at most 3, SH order at most 2, and at most
256 frequency bins, with the same directivity resampling as accurate runs.
If an RIR grid needs reduction, preview shows
only its RTF; an irregular subset is never passed into an inverse FFT. Run
accurate DEISM for the RIR. Failed previews clear obsolete curves.

Numeric values appear only in their controls, with units on the labels.
Question-mark help opens on hover, keyboard focus, or click/tap; Escape dismisses
it. Run metadata is collapsed under **Run details**, while errors, material review
requirements, preview/accurate/stale status, and the result archive path remain visible.

The directivity view supports pointer drag and arrow keys to orbit, plus
**Reset view**. Orbiting changes only the camera; acoustic Euler angles remain
unchanged. The view rotates gently around the z axis when idle, pauses during
dragging, and resumes from the released view.

Each plot supports wheel/trackpad horizontal zoom, pointer drag to pan, and
**Reset view**. RTF uses a logarithmic frequency axis; RIR uses linear time.
Navigation never reruns DEISM. Views persist while the domain is unchanged
and reset when its endpoints change. A single-frequency RTF is drawn as a dot.

Native runs use the Python fluctuation workflow and seed semantics. The offline
JavaScript generator is independent, so its seeded draw differs from Python.

## Build and validation

From the repository root with DEISM installed:

```bash
python tools/playground_directivity.py
python tools/playground_fixtures.py
cd playground && npm test
cd ..
python tools/playground_build.py
```

For source development, serve the repository locally over HTTP (bound to `127.0.0.1`) and open
`playground/src/index.html`; it loads the same generated `playground/data/`
files loaded on demand. To use the built browser demo, run `python -m http.server --bind 127.0.0.1 --directory playground` and open `http://localhost:8000/demo.html`. Opening HTML with `file://` cannot load the datasets. The tracked HTML is generated from `src/` and
`engine/`; do not edit it by hand.

`.github/workflows/playground-tests.yml` regenerates datasets and Python
fixtures, runs the Node tests, and builds the page. Missing datasets fail the
tests. Golden comparisons reject non-finite values and cover shoebox/convex
geometry, heterogeneous complex wall impedance, absorption/T60, directional
ORG/LC/MIX, and RIR. Application tests cover snapshots, wall identity, input
validation, rotation, mode controls, preview limits, and plot navigation.

The UI exposes single-band wall materials. Multiband materials are rejected by
the native contract; they remain available through Python scripts. Direct-path
removal is supported by the contract but has no UI control; environment constants
use Python defaults. The dependency strip describes a full run.

Measured results and platform scope: [native_validation.md](native_validation.md).

## Native contract and validation

The local POST `/run` request is `{version: 1, id, params}`. `params` is the
existing UI parameter object plus convex `wallCenters` in material-row order.
World coordinates are already rotated; `roomRotation` rotates only the acoustic
orientation frames in Python. Shoebox rows are x-/x+/y-/y+/z-/z+. Sampled data are
referenced by catalog ID; no embedded dataset is sent to Python. The receiver
alias for a duplicate filename resolves within the receiver directory.

Responses are newline-delimited `progress`, `stage`, `error`, and `result`
objects with the dispatch ID. Results contain full frequencies, split real and
imaginary RTF arrays, optional RIR, counts, geometry/material fingerprints,
per-stage milliseconds and backend provenance. RTF is captured before the
Python RIR bandpass window. The UI retains dispatch snapshots and marks results
stale after control edits. POST `/cancel` takes the dispatch ID. Writes require
a per-launch token and matching localhost origin; no remote binding is offered.

Run focused checks and the sequential benchmark from a development checkout:

```bash
python -m pytest tests/test_playground_native.py
node benchmarks/playground_presets_bench.mjs --dump-params /tmp/deism-presets.json
NUMBA_NUM_THREADS=10 python benchmarks/playground_native_bench.py \
  --params /tmp/deism-presets.json --out outputs/playground_native/acceptance.json
```

The benchmark uses the same installed package and thread count in both
processes. It compares direct public-Python execution against the HTTP runner,
with a cold pair followed by three sequential warmed pairs per case. Frequency
grids, image counts, path descriptors and material assignments must match
exactly. Complex RTF and RIR use `rtol=1e-6`, `atol=1e-9`, rejecting non-finite
values. The median computation gate is `native <= 1.2 * direct + 250 ms`.
Cold-stage timings include first-use JIT/cache initialization; dataset loading,
HTTP overhead and browser latency are reported separately. To isolate actual
Numba compilation events at unchanged publication settings, use a fresh cache:

```bash
NUMBA_CACHE_DIR="$(mktemp -d)" NUMBA_NUM_THREADS=10 \
  python benchmarks/playground_native_bench.py --jit-cold \
  --params /tmp/deism-presets.json --only jasa_fig8_config1,iwaenc_fig5 \
  --out outputs/playground_native/jit.json
```

Compilation duration is measured using Numba's compilation event timer. The native runner
does not remove inherent solver costs: IWAENC convex enumeration can remain slow.

The publication cases retain JASA Fig. 8 configurations 1–2 at order 25 with
ORG, SH order 5 and the full 491-bin grid, and IWAENC Figs. 5–6 at order 15.
Additional cases cover RIR/fluctuations, rotated directional rooms, and complex
heterogeneous walls. Counts are measured from the current native implementation,
never set from historical JavaScript/native counts.

Completed local runs are saved under `results/<preset>_YYYYMMDDhhmmss/result.json` (local start time) in the writable playground root. The Run button shows that folder, and the completed-run summary shows the file path. Each file includes the dispatched parameters, preset name, complex RTF, optional RIR, and result metadata. Same-second runs receive a numeric suffix. Changing controls keeps the active run available through **Cancel previous**; completed results retain their original preset identity. Automatic folder saving requires the local launcher; standalone browser files cannot write beside themselves.
